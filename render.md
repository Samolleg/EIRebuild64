# Отрисовка движка ПЗ
Для 3D отрисовки модели на экране, нужно передать в DXD3D координаты треугольников, из которых она состоит. 
Каждый треугольник описывается (логично) тремя вершинами. У каждой вершины заданы свойства - координаты, цвета и т.д. 
В варианте ПЗ/DX7, треугольники должны быть переданы в экранных координатах, например от 0 до 800x600. 

Для этого, в общем случае, нужны преобразования от координат вершин внутри модели/запчасти, 
к координатам объекта (из моделей),
к координатам мира (в котором расположен объект), 
к координатам камеры (которая захватывает мир с определенной точки), и наконец к экранным координатам.

Преобразования, в основном, осуществляются при помощи матриц - перемножением матриц и исходной вершины.

Конечной точкой этого процесса является записывание свойств вершин в необходимый формат (e.g. STLVertex)
с передачей в DrawPrimitive/IndexedPrimitive. При отрисовке конечных вершин, их свойства/координаты интерполируются.

На момент разработки ПЗ преобразование вершин на видеокарте (Hardware T&L) было сравнительной экзотикой 
(первая способная к этому карточка - GeForce 256, вышла в 1999). 
Поэтому эти этапы выполняются на процессоре:
CTLPipelineFPU::LightVerticesDfPt вычисляет цвет вершины с учетом источников света.
Преобразование вершин либо выполняется в один этап при помощи TransformVertices (для моделей, 
которые полностью помещаются на экран, TRV_VISIBLE_NOCLIP), с выводом вершин в экранных координатах. 
Либо в два этапа через вызов TransformVertices с выводом в координатах проекции (обычно для обрезки не-помещаюшихся моделей TRV_VISIBLE_CLIP), 
с дополнительным вызовом CastProjectionToScreenС.

Видеокарта же здесь отвечает за 
1) растеризацию / отрисовку треугольников
2) текстурирование
3) вершинный туман 
4) смешивание прозрачности
5) антиалиасинг.

##Текстурирование 
На современных видеокартах и современных API переданные вершины обрабатываются пользовательскими программами на стороне видеокарты.
В минимальной конфигурации это вершинный и пиксельный шейдеры. 
Вершинный шейдер преобразует вершины - их цвета, координаты, рассчитывает освещение.
Пиксельный шейдер вычисляет цвет текстуры, а затем пикселя на экране.

Аналог пиксельного шейдера у DX7 управляется через текстурные блоки, SetTextureStage(nStage, op, value), 
которые описывают, что делать с текстурами. У ПЗ есть 3 основных текстурных блока, различающихся работой с альфа-каналом. 
В зависимости от режима, альфа конечного пикселя берется как:
1) dwTextureAlphaStateBlock / am_texture - альфа текстурного пикселя // блок по-умолчанию, эквивалент dwDefaultStateBlock
2) dwModulateAlphaStateBlock / am_multiply - произведение альфы текстуры и альфу вершины // отвечает за прозрачность воды
3) dwDiffuseAlphaStateBlock / am_multiply  - альфа вершины.
RGB конечного пикселя всегда берется как произведение текстурного пикселя и цвета вершины.

ПЗ использует для отрисовки модели одну текстуру, с одним исключением - для отрисовки крови на моделях используется вторая текстура, накладываемая
поверх первой (SetTexture(1, ...), SetTextureStage(1, ...)).

## Вершинный "туман"
Т.к. ПЗ не использует аппаратное освещение, туман должен рассчитываться приложением, о чем нам сообщает документация D3D9:
https://learn.microsoft.com/ru-ru/windows/win32/direct3d9/vertex-fog
При включении и использовании тумана, приложение должно рассчитать фактор тумана fogFactor 0..1 и 
поместить его в альфу specular компоненты цвета у вершины: vertex.dwSpecular = MAKE_RGBA(R, G, B, fogFactor);

Достаточно просто. Однако, в целом происхождение dwSpecular может быть весьма туманным:
1) Может быть получено из значения по-умолчанию, заданного в функции Object::Draw (если установлен флаг USE_DEFAULT_COLORS)
2) Может быть загружено из самой модели (CSkyObject), при условии соответствующих флагов USE_DEFAULT_COLORS / FIG_LIGHTED;
3) Рассчитано функцией IsAddFog/AddFog для удаленных объектов в сцене;
4) Рассчитано на краях ландшафта функцией CTerrain::GetFogAlpha;
5) ...

## Детали
Cистема координат у DirectX7 левая - X направо, Y вверх, Z вглубь. Прямой порядок вершин по-умолчанию - по-часовой.
https://learn.microsoft.com/en-us/windows/win32/direct3d9/coordinate-systems
ПЗ использует D3DRENDERSTATE_CULLMODE::D3DCULL_CW, чтобы использовать порядок вершин против часовой как прямой.

За трехмерную сцену отвечает матричный стек MAT_STACK_PROJSPACE. На стек накидываются (PushMainMatrix/PushMatrix) следующие матрицы в соответствующих функциях:
MAT_STACK_CLIPSCALE						@ CVisualizatorD3D::Create
MAT_STACK_PROJECTION					@ CVisualizatorD3D::Create
MAT_STACK_CAMERA						@ CWorldClient::Draw
Object->GetPlacement					@ CObject3DClientSpecific::Draw
CObject3DClientSpecific::GetScaleMatrix @ CObject3DClientSpecific::Draw
pFigure->GetPlacement(matrix)			@ CObject3DClientSpecific::Draw

Основный вызов отрисовки - NGame::DrawFrame, в котором выполняется theInterface.Draw, затем theInterface.Draw2D (DirectDraw).
theInterface.Draw рисует "серый" задник (из заранее полученного скриншота) и верхний экран в стеке.
Верхний экран (самый основной - I3DScreenMission, игровая сцена) обычно рисует все дочерние объекты (CObject3D/spec), которые рисуют все фигуры /запчасти (CFigure/spec).

I3DScreenMission::Draw рисует мир (CWorldClient::Draw), затем интерфейс.
CWorldClient::Draw рисует скайбокс, террейн, 3D сцену (объекты, юниты, эффекты/частицы).
