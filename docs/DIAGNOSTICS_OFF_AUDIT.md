# Аудит работы без диагностики — DIAGOFF01

## Объём и критерий

Аудит выполнялся по исходникам EIRebuild64 и собственного embedded renderer на базе
4a35f0f. Проверены все прямые использования RuntimeDiagnostics::Enabled (22 файла),
потребители состояния CorePerf, счётчики, изменяемые внутри диагностических условий,
и вспомогательные frame_accounting/frame_waits/RenderProfiler/bridge-profile ветки.
Проверены Game, Navigation, Pak, shared, ScriptCheck/ScriptCompilerCore и Source/Host
собственного рендера. Чужие SDK и библиотеки не изменялись.

Критерий: отсутствие --diagnostics не должно останавливать обязательное выполнение.
Измерения, подробные журналы и GPU timestamp-запросы могут отсутствовать. Наличие
--background включает диагностику по действующей политике; такой запуск сам по себе
не является доказательством работы обычного режима.

Это аудит условных зависимостей с целевыми исполняемыми регрессиями, а не прохождение
всей кампании или проверка каждой комбинации видеокарты, API и генерации кадров.

## Найденные дефекты и исправления

1. **Навигация:** NavigationWorld::Find использовал CorePerf::Get().frameNumber.
   CorePerf::Frame увеличивает его только при активном профилировщике. В обычной игре
   общий бюджет пути исчерпывался, а следующий гарантированный пакет sliced search
   не выделялся. Команда движения оставалась в Updating.
   Добавлен независимый RuntimeFrame в обычный и фоновый циклы. PathWorkBudget
   возобновляет 2 мс на итерацию; PathProgress даёт каждому юниту один ограниченный
   пакет работы независимо от затрат предыдущих юнитов. Профилирование не включается.
2. **Модели в интерфейсе:** frameSerial в RendererDX11 увеличивался внутри условия
   RuntimeDiagnostics. ModelPreviewFrame использует его для определения непрерывности
   отображения модели. При выключенной диагностике возврат после пропущенных кадров
   ошибочно считался продолжением того же кадра. Счётчик теперь продвигается при каждом
   успешном Present; условие диагностики управляет только записью измерений.
3. **Достоверность MCP:** нулевой fps при выключенных измерениях выглядел как результат
   замера. Status теперь возвращает diagnostics_enabled/fps_available; Perf явно
   сообщает available=false и reason=diagnostics_disabled. Игровые данные, команды,
   навигационные запросы, операции и снимки не требуют включения диагностики.

## Исполняемые проверки

`tools/check-diagnostics-off.ps1 -OutputDirectory <task>/checks`:

- Без флагов: PASS, 38 проверок. Старый CorePerf clock действительно воспроизводит
  Updating на 8 последовательных попытках; новый путь завершается за 3 итерации.
- --diagnostics: PASS, 29 проверок, путь за 3 итерации.
- --background: PASS, 29 проверок, путь за 3 итерации (это консольный тест, не запуск игры).
- Во всех режимах: маршрут 254 м, 41 точка; собственные исходники Recast/Detour,
  действующие Query/Build и prepare_model_preview_phase. Проверены возобновление
  бюджета, отсутствие повторного бюджета в одном кадре и отдельный прогресс второго юнита.
- Выключенные CorePerf/E1/E2-измерения остаются выключенными.

`tools/check-audit-fixes.ps1` без диагностики: PASS, 222 проверки, включая
чтение реального RES с 3167 записями, некорректные RES-заголовки/границы,
PAK mount/decode/enumeration, идентичность мода и ключи отказов навигации.
Повтор того же exe с --diagnostics: PASS, 222 проверки. Приватные данные,
временные файлы и результаты находятся только в каталоге задания, не в Git.

## Статус

Целевые тесты пройдены; Release x64 сборка завершена кодом 0 за 87,5 с. Комплект создан, проверки зависимостей и подписей DLL прошли. Открытая игра владельца
не закрывалась, установленная версия не изменялась. Обычный игровой запуск после
установки, восстановление движения героя и внешний вид моделей UI остаются
приёмкой владельца: фоновый MCP-запуск включает диагностику и не заменяет её.
