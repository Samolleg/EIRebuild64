# samastrift01--04 and samastrborder01: animated astral veils

For the rift family, the effect selects exactly `samastrift01`, `samastrift02`, `samastrift03`, `samastrift04` (optional `.mod`, ASCII case-insensitive). Model 01 selects only `empty_veillow`, `empty_veilcrown`, `empty_veilcross`, `empty_veilwake`; models 02--04 select only `empty_veils`. The border has its own exact selection described below. Stone, core, `empty_astraldepth` and `empty_astralfilaments` geometry, textures and transforms are unchanged. There is no gameplay effect, new resource archive or setting.

`astral_rift.h` adds immutable generated parts to the completed appearance. Model 01 keeps its original four parts and exact sampling order (32 clumps, 256 triangles). The combined `empty_veils` FIG in 02--04 is partitioned by triangle/position connectivity: four ribbons in 02 and 04, two in 03. Eight crossed, double-sided clumps are sampled from each ribbon's authored UV edge, producing 32/16/32 clumps and 256/128/256 triangles respectively in one generated part per model. This prevents repeated UVs from concentrating all births on the first ribbon. They share the veil's skeleton node, texture and material, inherit its hidden state and disappear with the same appearance lifecycle. Completed host appearance updates resolve these generated parts through the original skeleton node, not a nonexistent host figure. Generation is idempotent, including initially hidden veils.

The installed FIG1 resources of 02--04 use the same `samastrtex01` atlas. Their veil UV rectangle is inset one additional texel per side relative to 01 and remains inside the existing shader rectangle. No shader or resource edits are needed; the owner-verified movement of 01 is preserved. Family inspection and per-model acceptance are recorded by task ASTRAL-RIFT-FAMILY01.

`samastrborder01` (also optional `.mod`, ASCII case-insensitive) selects only `empty_boundaryveils`. The installed FIG1 has four connected surfaces (402/224/224/224 source vertices) using the exact shader UV rectangle and the same `samastrtex01` atlas. It receives 32 clumps (256 triangles), eight per surface, through the existing connectivity partition. `empty_bank`, `empty_threshold`, `empty_astralslates`, and `empty_astraldepth` remain static. A part named `empty_veils` is deliberately not an alias on the border, nor is `empty_boundaryveils` an alias on the rifts. No GPU shader, authored model, texture or map changes are required. Task: ASTRAL-BORDER-GPU01; in-game appearance still needs owner review after installation.

Owner correction (ASTRAL-BORDER-TEXTURE01): remove only the torn texture from the boundary surfaces. `EMPTY_BoundaryVeils` now samples an immutable 1x1 violet texel (RGBA 189/171/233/255, sampled from the original atlas's plain region) instead of the torn pattern/alpha holes. The original geometry, UVs, material response and installed animation remain unchanged. Clumps copy the original source atlas before the veil-only override, preserving their existing transparent pattern and fading. Other parts/models still use their original textures. The rejected ASTRAL-BORDER-SMOOTH01 geometry reconstruction and new pulse are not included. No installed MOD/MMP is rewritten.

Correction ASTRAL-BORDER-ALPHA01: the alpha=255 texel above produced an opaque wall and is superseded. The texel now has alpha=48 with no opaque-mip proof and a new generated-value serial. Only the boundary veil's material opacity receives a six-second sine pulse (0.70--1.00), applied to both material alpha and packed default-colour alpha for the lit/unlit paths. RGB, source geometry/UV and clumps stay unchanged. At full source-material opacity each sheet contributes 13.2--18.8% alpha; four overlapping sheets still transmit at least 43.4% of the background. The existing dynamic-part alpha blend, low alpha-test threshold and disabled depth writes remain in force.

The targeted check also uses a windowless Direct3D 11 WARP device: it uploads the production BGRA texel, applies the production pulse values, draws one/four layers using SRCALPHA/INVSRCALPHA, reads pixels back and compares with the expected visible background. This tests compositing, not the full game scene; the in-game visual still requires review.

`NativePreparedPartValues::astral` and the matching GPU/HLSL layout carry normalized logical time, effect kind and veil phase. Logical time is `GetPreciseTime()` in 55 ms quants; the period is six game seconds. No wall-clock accumulator, particle allocations or retained game-object pointers are used. Pausing the logical clock pauses the effect; loading a different clock directly reconstructs it.

The world vertex shader adds a small local wave to veil positions (maximum Z amplitude 0.28), leaving their endpoints fixed. Clumps move along a local tangent and outward/upward, then fade out before wrapping. Displacements are transformed by the same node matrix as the model, so placement, rotation and scale apply to the effect.

The pixel shader scrolls two texture samples within U `[0.0166015625, 0.4833984375]`, preserving the original veil V coordinate. Complementary sine-squared weights remove the visible wrap seam without reading another atlas quadrant. Clumps use V `[0.5166015625, 0.9833984375]`, a soft spatial mask and lifetime alpha. Source gradients are retained across the wrap. Both regular and Low material shader paths use the effect.

These transparent parts preserve draw order, use no depth writes and cast no shadows. Stones retain their existing shadow policy. The model leaves the persistent static-color set; effect parts do not use static mesh LOD simplification. Conservative object/part envelopes include the maximum displacement (0.5 for waves, 7 for clumps). Geometry and world-pose caches retain the resting data; color deformation runs after cached world vertices are read.

Validation command: `tools/check-astral-rift.ps1 -OutputDirectory <task>/check`. Covers exact model/part selection, unrelated-model exclusion, preservation of source geometry and stone shadow policy, generated indices/finite coordinates, stable count/idempotence, initially-hidden inheritance, and atlas coordinate bounds. Full x64 build compiles the production shaders; this does not establish in-game visual acceptance. Review after an explicitly authorized installation: existing placed samastrift01 from all sides, pause/resume, camera/frustum edge, rotated/scaled placements, hide/show, map transition, alpha overlap with rocks, and multiple instances. No installation is part of this change.
