# Выгрузка персонажей и вещей из Blender

Инструмент `tools/character-export/export.py` предназначен для Blender 5.2
(на рабочей машине — 5.2.2 LTS). Правила загружаются из
`Data/profiles/human.v1.json`; смысл полей описан в [профиле](character-profile.md).
Инструмент не устанавливает модель и не меняет исходный `.blend`.

## Подготовка

Работайте в отдельной авторской копии сцены. Создайте коллекцию для каждого
экспортируемого ресурса: тело с волосами, отдельная одежда, отдельный предмет.
Передавайте её через `--collection`. Без этого параметра проверяются все объекты
активной сцены: меч и щит внутри экспорта тела будут ошибками неподвязанной сетки.
Камеры и источники света в экспорт не включаются.

Установите Metric, Unit Scale=1. Оси авторской сцены Blender: +Z вверх, −Y вперёд.
Стандартный экспортёр glTF переводит их в +Y вверх, +Z вперёд ровно один раз.
Все объекты модели должны иметь единичные мировые трансформы. Скелет сохраняет
имена, родителей и rest pose профиля; корень — в начале координат. Не применяйте
сохранённый масштаб сцены к rest pose: подготовьте сетку и арматуру согласованно.
Обязательные кости и предки должны присутствовать, неизвестные кости запрещены.
Модификаторы геометрии, включая Geometry Nodes, нужно запечь в экспортной копии;
Armature остаётся. Веса каждой вершины — нормированные, неотрицательные, максимум
`gltf.maxJointInfluences` из профиля. Экспортёр не исправляет и не обрезает их молча.

Сокеты тела — Empty с точными именами из профиля, parent type BONE, parent bone
из поля `parent`. Их локальные рамки берутся из профиля. Учитывайте, что Blender
добавляет смещение к хвосту кости при bone parenting; численные TRS профиля
заданы относительно начала кости и в осях профиля. Для преобразования в Blender
используйте `inverse(C) × Lsocket × C`, затем компенсируйте хвост и parent inverse.
Ориентация предмета задаётся его собственной рамкой grip: +Y от рукояти к острию,
+Z — режущая кромка/прицел в системе профиля. Геометрический смысл направления
лезвия требует авторской оценки, автоматическая проверка проверяет численные рамки.

Свойство сцены `ei` содержит JSON-строку (или Blender IDProperty group), например:

```python
import bpy, json
bpy.context.scene['ei'] = json.dumps({
    'profile': 'human.v1', 'kind': 'body',
    'morphSet': 'human.default.v1', 'morphs': [], 'bindings': []})
```

`--kind character` соответствует metadata kind `body`, `clothing` — `garment`,
`item` — `rigid-item`. Для одежды дополнительно задайте `hides`: список уникальных
зон из профиля, включая пустой список, если тело не скрывается. Для предмета
задайте `socket` и явный `grip` с translation/rotation/scale, например из
`metadata.item` профиля. Примеры metadata в профиле не подставляются автоматически:
нельзя угадать маску одежды или хват предмета.

Каждый материал тела получает строковое custom property `ei_zone` со значением
из `zones` профиля. Разделите сетку на material primitives по границам зон.
Несколько primitives могут иметь одинаковую зону. Одежде и предметам зоны тела
не присваиваются. Используйте Principled BSDF напрямую в Material Output,
core metallic-roughness без transmission/coat/sheен и прочих расширенных эффектов.
RGB baseColor/emissive — sRGB, normal/ORM — Non-Color. Alpha означает прозрачность;
не кодируйте ею раны, свечение или класс материала. Проверка не определяет смысл
нарисованных пикселей. PNG/JPEG должны быть доступны Blender, иметь ненулевые
размеры и TEXCOORD_0. Любой texCoord≠0 и KHR_texture_transform запрещены.
Normal map требует авторский TANGENT, экспортёр проверяет фактический float VEC4
и единичный базис с w=±1. Фактический GLB не должен содержать внешних URI.
Числового бюджета размеров текстур в human.v1 нет: инструмент сообщает это
предупреждением, не придумывает ограничение.

Морфы задаются одинаковым упорядоченным набором shape keys (после Basis) на
экспортируемых мешах. `scene.ei.morphs` содержит записи `name/min/max/default`;
slider ranges и текущие значения keys должны совпадать. Без морфов задайте
`morphs: []` и общий идентификатор morphSet тела и одежды. Совпадение двух разных
файлов тела и одежды нужно сверить перед публикацией: одиночный экспорт проверяет
только согласованность metadata и геометрии своего файла.

## Анимация и события

Базовые actions тела должны иметь точные имена из `clips` профиля.
Обязательные клипы текущего среза заданы `animation.exportRequiredClips`
(сейчас `idle`), полный набор `clips[].required` относится к следующему этапу. NLA tracks
не поддерживаются этим путём: запеките их в отдельные actions. Запекайте constraints
и корректоры в представимые TRS/weights; движения в пространстве остаются у игры.
Экспортируются actions одной арматуры с полным sampling, rest pose задаёт bind.

Маркеры action задают события. Имя маркера — `имя:JSON-payload`, например
`footstep:{"foot":"left"}`, `hit:{}` или `release:{}`. Время вычисляется относительно
начала action с учётом FPS сцены. ID генерируется из номера маркера. Альтернатива —
JSON-свойство action `ei` с массивом `events` (id/name/time/payload), где время уже
в секундах от начала клипа. Не дублируйте одно событие обоими способами.
События сортируются по time/id и записываются в `animations[].extras.ei.events`.
Повторные ID, недопустимые имена/payload, события за пределами клипа и отсутствие
обязательных событий являются ошибками. `scene.ei.bindings` переносится в asset
extras; проверяются обязательные поля, ссылки на клипы и повторные request tuples.
Игровой ADB fallback и фазовое согласование с конкретным ADB относятся к интеграции
в движок; инструмент не подтверждает их игровой прогон.

## Запуск

### Исправление рассогласованной привязки

Совпадение имён костей и inverseBindMatrices не доказывает правильную привязку
сетки. Если геометрию и rest-скелет нормализовали разными матрицами, первый idle
уже в самом GLB растягивает пальцы и смещает волосы относительно тела.
У исходного дефектного GLB максимальное растяжение ребра составляло 39,69 раза;
индексы UNSIGNED_SHORT, включая значения выше 255, сохранялись правильно.
JOINTS_1 отсутствовал, суммы весов и bind-матрицы были согласованы.

`rebind.py` читает авторскую сцену и подготовленную копию, сохраняет UV,
материалы и профильный rest-скелет подготовленной копии. Геометрию он переводит
в систему арматуры и вычитает rest-корень **той же матрицей**, которая применяется
к деформации костей. Для каждого кадра выбранного action запекается
`N × sourcePose × inverse(sourceRest) × inverse(N) × targetRest`.
Объектное движение арматуры относится к размещению персонажа и не применяется
к сетке второй раз. Имена мешей, топология и именованные веса должны совпадать;
активные морфы и анимированные контейнеры сеток отклоняются; запись поверх входных
файлов запрещена. Это инструмент перепривязки существующей подготовленной копии,
а не автоматическая подготовка произвольной сцены или ретопология.

```powershell
& 'C:\Program Files\Blender Foundation\Blender 5.2\blender.exe' --background --python tools/character-export/rebind.py -- --source C:\work\author.blend --prepared C:\work\prepared.blend --action 'Author idle' --out C:\work\corrected.blend
& 'C:\Program Files\Blender Foundation\Blender 5.2\blender.exe' --background C:\work\corrected.blend --python tools/character-export/export.py -- --kind character --collection BodyExport --out C:\work\corrected.glb
```

Для Налы входы: `tasks/NALA378/armed-key-draft.blend`,
`content/models/characters/nala-gltf/nala.prepared.blend`, action `Nala / cidle01`.
Результаты сначала сохраняйте в каталоге задания; исходники и content инструмент
не перезаписывает. Нужна **новая выгрузка**, замена одного EXE старый GLB не исправляет.

Экспортёр запекает вычисленные Blender world-рамки костей. Между родителем и
суставом добавляется non-joint узел компенсации масштаба: его масштаб обратен
мировому масштабу родителя. Это сохраняет Blender `inherit_scale=NONE`, который
нельзя передать простым разложением `inverse(parent) × child` в TRS без потери shear.
Quaternions соседних отсчётов согласуются по знаку. Непредставимый остаточный shear
отклоняется; оба входных BLEND остаются без изменений.

Общий CPU-декодер игры и ModelCheck проверяет рёбра после первого idle с теми же
16-битными весами, которые получит GPU. Профильный `gltf.maxIdleEdgeStretch=10`
отклоняет катастрофическое растяжение более чем в десять раз; рёбра короче 1 мкм
не используются для этой проверки. Это предохранитель от повреждённой привязки,
а не полная художественная оценка, проверка всех кадров или отдельный детектор
дыр в волосах. Предел относится к профилю, без ветвлений по имени модели.

Разовая CPU-сверка исправленной Налы с вычисленной геометрией авторского первого
idle: максимум 4 мкм по телу, 0,27 мкм по волосам; максимальное растяжение ребра
2,70 раза. Отдельная сверка фактического результата общего C++-декодера с раскладкой
GPU-матриц дала максимум 5,11 мкм относительно авторской сцены (волосы 0,39 мкм).
Эти измерения не подтверждают изображение на GPU или игровой прогон.

Перед запуском скопируйте `EIRebuild64ModelCheck.exe` из соответствующего комплекта
сборки рядом с `tools/character-export/export.py`. Без EXE экспорт завершается
ошибкой и сохраняет существующий выходной файл. Утилиту можно вызвать без Blender:

```powershell
.\EIRebuild64ModelCheck.exe C:\work\body.glb --profile Data/profiles/human.v1.json
```

Экспорт и `--check-glb` вызывают общий с игрой C++ CPU-декодер. Код 0 означает
приём, 1 — отказ, 2 — неверную командную строку. Отдельная Python-проверка
приёма готового GLB удалена; проверки подготовки сцены остаются.
Текущий игровой путь принимает `body`; `garment` и `rigid-item` получают отказ
общего декодера до реализации их игрового пути.

Из корня rebuild64 (замените пути на свои):

```powershell
& 'C:\Program Files\Blender Foundation\Blender 5.2\blender.exe' --background model.blend --python tools/character-export/export.py -- --kind character --collection BodyExport --out C:\work\body.glb
```

Для одежды используйте `--kind clothing`, для меча/щита/шлема — `--kind item`.
`--profile path.json` выбирает файл контракта той же схемы/версии.
Для повторной проверки существующего GLB (также через Blender Python):

```powershell
& 'C:\Program Files\Blender Foundation\Blender 5.2\blender.exe' --background --python tools/character-export/export.py -- --kind character --check-glb C:\work\body.glb
```

Сначала проверяется исходная сцена. При ошибках экспорт не запускается. Затем
штатный glTF exporter создаёт временный GLB рядом с выходным файлом; в нём
сохраняются игровые extras. Общий C++ декодер проверяет сериализованный GLB,
включая профиль, bind/inverseBind, геометрию, изображения и начальную позу.
Только после этого файл атомарно публикуется по `--out`.
Существующий результат при отказе сохраняется. Ошибки выводятся в `ERRORS`
с местом и способом исправления, предупреждения отдельно в `WARNINGS`.
Код процесса 1 означает отказ, 0 — прохождение доступных проверок.

Техническая проверка подтверждает приём тем же CPU-загрузчиком, но не заменяет
визуальную приёмку цвета, хвата, деформаций и видимости в игре.
Инструмент выгружает только активную сцену и согласованно приводит рамки
суставов, inverse bind, сокеты и TRS-анимацию к базису профиля перед
проверкой сериализованного GLB.

## Runtime анимаций (X64GLTF09)

Runtime сохраняет TRS/weights всех клипов. Общее вычисление позы D3D11/D3D12
выполняет STEP, LINEAR и CUBICSPLINE (тангенты умножаются на интервал ключей),
нормализует кватернионы, использует shortest-path SLERP и собирает иерархию.
Морф-дельты позиции/нормали/тангента применяются к исходной вершине до skinning.
Нулевой/отрицательный scale и кубический scale с hull, достигающим нуля,
отклоняются профилем; кубический кватернион, приближающийся к нулю, также отклоняется.
Границы отсечения охватывают все ключи, кубические Bezier hull и переходы;
это консервативная сфера, а не точная покадровая оболочка.

`asset.extras.ei.bindings` принимает `{legacyClip, clip}` либо плоский объект
`{state, action, stage, weaponMask, modifierBits, clip}`. State/action/stage —
числовые ADB bits или имена: neutral/rest/attack/warry/lie,
special/attack/cast/run/walk/idle/death/suffer/cross, unique/start/cycle/end.
Порядок выбора задан `animation.fallbackOrder` профиля. Rest/lie и специальные
cross/special с кодом требуют явной привязки. Отсутствующее действие — ошибка
с именем исходного ADB-клипа, без подмены на idle или legacy-геометрию.

Время клипа определяется фазой ADB, делённой на длину записи; обычные действия
останавливаются в конце, циклические повторяются. Переход занимает 120 мс от
последней показанной позы предыдущего клипа; повторное переключение внутри
перехода, перемотка и death переключаются сразу. Игра остаётся владельцем
перемещения, попаданий, снарядов, звуков и видимости оружия.

События GLB сверяются с ADB с допуском одного исходного кадра. События hit/release,
footstep, sound и attachment_visibility не создают повторных игровых эффектов;
визуальные уведомления пишутся только в приватный диагностический журнал.
Первое появление, восстановление и обратная перемотка не воспроизводят историю;
повторная выборка одного кадра не дублирует события. Приватные превью их не посылают.
`action_end` допускается только в конце клипа. Нехватка событий или несовпадение
фаз требует отдельной привязки/авторского клипа, а не отключения проверки.

Проверка `tools/check-gltf-animation.ps1 -OutputDirectory <папка задания>`
исполняет production nativePoseCS через D3D11 и D3D12 WARP с readback,
а также production skinning через D3D11 WARP,
сверяет их с CPU reference и проверяет malformed данные, bindings, фазы,
события/seek и переходы. Это проверка обоих API на программном адаптере, не игровой прогон на видеокарте.
Опции `-Glb <файл> -Profile <профиль>` добавляют декодирование реального GLB и
сверку трёх поз idle; перед этим нужен cgltf из `tools/prepare-worktree.ps1`.
ModelCheck печатает также объём анимаций и радиус консервативной оболочки.
Установленный Нала-GLB с одним idle требует отдельного комплекта клипов и bindings
перед игровой установкой этого runtime. Полная приёмка шага 3 остаётся открытой.
